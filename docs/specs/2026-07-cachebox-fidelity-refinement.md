## 1. Target design — invariants

The refined flow is the same three stages (RECORD → EXPORT → PRELOAD → replay), restated as invariants each stage must uphold. Task IDs in section 3 reference these.

- **INV-1 (fail-closed freeze).** During an isolation phase, a request whose cache-box decision is `replay` or `replay_with_delay` is NEVER forwarded to the live downstream and NEVER written to the store. Hit → recorded response; miss → synthetic miss response + counter. There is no configuration that re-opens this path.
- **INV-2 (authoritative, symmetric keying).** The cache key for a request is a pure function of (strategy id, strategy version, per-rule header allowlist, request), where strategy id/version/allowlist are delivered by the control plane on the rule/freeze command. The same function with the same parameters runs at record time and replay time; the control plane verifies this symmetry at preload and refuses to preload on mismatch.
- **INV-3 (complete, verified export).** A recording phase reaches `completed` only after every expected SDK instance has flushed and drain-reported, and per-instance `entries_received_by_manteion == entries_recorded`. Any shortfall is an explicit, machine-readable degradation on the phase, and dependent isolation phases refuse to start from a degraded recording by default.
- **INV-4 (exact preload).** At load start of an isolation phase, every instance of every frozen service holds a replay set that is byte-verified (count + order-independent checksum) equal to manteion's stored recording for the source phase, was installed by atomic replace (never merge), and cannot be evicted or mutated for the life of the phase. Preload failure on any instance aborts the phase before the freeze is asserted and before load starts.
- **INV-5 (phase-scoped provenance, no ambient state).** Every recorded entry, push batch, preload, counter, and stored file is stamped with `(experiment_id, phase_id)` derived from the matched rule or command that authorized it — never from a global "most recently started phase" lookup. Two concurrent experiments can only interact by explicit admission-control decision, not by accident.
- **INV-6 (measurable fidelity).** Every isolation phase yields, per instance, counters sufficient to compute a first-class verdict `VALID | VALID_WITH_WARNINGS | INVALID(reasons[])` stored on the phase. Any freeze miss, preload incompleteness, drain degradation of the source recording, or missing telemetry ⇒ `INVALID`. `SEAM(D)`: the decomposition math must consume this verdict and refuse to compute over `INVALID` runs — not implemented here.
- **INV-7 (no silent loss).** Every drop, rejection, eviction, timeout, or fallback anywhere in the pipeline increments a counter that reaches manteion. Log lines are never the only evidence.

## 2. Design decisions (the six questions)

### Q1 — Miss semantics under freeze

**Decision:** fail-closed, returning a synthetic **503** with `Content-Type: application/problem+json`, headers `X-Atropos-Cache-Miss: 1`, `X-Atropos-Cache-Key: <key>`, `X-Atropos-Cache-Mode: <action>`, and a JSON body `{"error":"cachebox_miss","key":...,"experiment_id":...,"phase_id":...}`. The miss increments `replay_misses{reason}` and is surfaced two ways: pulled by manteion in the phase-finish fidelity collection (authoritative), and any `replay_misses > 0` forces the phase verdict to `INVALID` (INV-6). The miss is NEVER recorded into the store. A single narrow knob exists: the control plane may override the status code per freeze context (`miss_status`, default 503) — the header, counter, invalidation, and no-record behavior are unconditional.

**Rejected:** empty 200 — the application treats fabricated data as real, may cascade writes, and an empty 200 is indistinguishable from a legitimately empty recorded response; worst possible option for an instrument. Fully configurable synthetic responses — pointless surface area: *any* miss already invalidates the run's delta math, so no return value can "protect" the measurement; the return value only controls blast radius, and 503 is honest ("this dependency is unavailable"). The one risk of 503 is caller retry policies amplifying load mid-run — acceptable because the run is already invalid the moment the first miss occurs; the `miss_status` override exists if a specific stack's retry storm makes debugging painful. Be explicit in code comments: the current miss-fallback (`cachebox.go:77`, "forward and record so the next request hits") is correct for a cache and disqualifying for an instrument; the two use cases must never share a code path again.

### Q2 — Drain barrier

**Decision:** option (a) as the spine, with batch sequence numbers from (b) kept as retry-idempotency keys, and a bounded window from (c) as the failure backstop. Concretely: a new `draining` phase state. On finishing a recording phase, manteion (1) CAS-transitions `running → draining` (winner-only side effects, same race discipline as today), (2) stops attacks, (3) bumps the rule version so SDKs observe recording end, (4) keeps the push endpoint accepting batches for that phase while `recording|draining`, (5) waits until every expected instance has sent a drain report and per-instance `received == entries_recorded`, bounded by `MANTEION_DRAIN_TIMEOUT` (default 30s; must be ≥ 3× SDK poll interval + flush time), (6) for silent instances at timeout, falls back to pulling `GET /cachebox/fidelity` from them to distinguish "instance dead" from "report lost", then (7) CAS `draining → completed` with a drain result `{status: clean|degraded, missing_instances[], shortfall}` persisted on the phase. Harvest runs after the gate, so coverage stats are computed over verified-complete data. The SDK, on observing recording end via the version bump, synchronously flushes remaining batches (with retry) and POSTs a drain report containing `entries_recorded / entries_pushed / entries_dropped / last_batch_seq`. Batches carry `batch_seq`, monotonic per `(experiment, phase, instance)`; manteion dedupes on `(exp, phase, instance, batch_seq)` so SDK retries are safe. Isolation phases (nothing recorded) skip the drain barrier; their telemetry is pulled, not pushed (Q6).

**Failure modes, per option:** (a) alone: instance crashes before reporting → the timeout + pull fallback converts a hang into an explicit `degraded` with the instance named; requires knowing the expected set — defined as *(registered instances of services holding recording rules for the phase) ∪ (any instance that pushed ≥ 1 batch for the phase)*, which also covers instances that appeared mid-phase. (b) alone: a sequence gap detector cannot distinguish "tail lost" from "no more batches" without a final-count message — it collapses into (a) anyway; kept only as the idempotency key, with server-side gap logging as free debugging. (c) alone: a quiesce sleep is an unverifiable timing prayer (GC pause, retry backoff, or slow poll defeats it) and leaves fire-and-forget drops invisible; it survives only as the bounded outer window so a dead instance can never hang an experiment.

### Q3 — Keying

**Decision:** introduce **`canonical_v2`** as the new default strategy and make the per-rule strategy authoritative end-to-end. Key = `"v2:" + hex(SHA-256(frame))` where `frame` is the concatenation, each component encoded as `uvarint(len) || bytes` (length-prefixing kills the delimiter-ambiguity in the current `|`-joined keys), of: strategy tag `"v2"`, uppercased method, lowercased host, raw path, canonical query (split `RawQuery` on `&`, byte-sort segments, rejoin — matches the existing `normalizeQuery` philosophy, no decode/re-encode pitfalls), header fingerprint, and SHA-256 of the raw request body (empty component when no body; replaces the weak FNV-64). Header fingerprint: allowlist = default `{accept, content-type, accept-encoding, accept-language}` ∪ per-rule `key_headers`; for each *present* allowlisted header, in sorted lowercase-name order, the line `name:` + values joined by `,`, lines joined by `\n`; absent headers contribute nothing (absence ≠ empty). Everything else — `Date`, `Authorization`, `Cookie`, `User-Agent`, `traceparent`, `X-Request-Id`, `Content-Length` — is excluded by construction. Because record and replay intercept at the same `RoundTripper` point, whatever bytes are seen there are the correct bytes to replay there; `Accept-Encoding` in the allowlist keeps compressed/identity variants from colliding.

**Authoritative end-to-end:** the strategy id, version, and `key_headers` travel on a `CacheBoxContext` attached to (i) compiled cache-box rules, (ii) the freeze command, and (iii) preload `begin` (wire spec §W). The interceptor derives the key from the *matched rule's* context, not from the construction-time `cb.DeriveKey`; the constructor strategy survives only as the fallback default (`canonical_v2`). Each exported entry records `(key_strategy, strategy_version)`; at preload, manteion verifies the recorded strategy equals the freeze context's strategy and refuses to preload on mismatch — turning what is today a silent 100%-miss into a preflight error. Since record and replay strategies must agree *across phases of one experiment*, strategy is validated at experiment creation: all phases touching service S must agree.

**Collision detection under 1-to-1:** on record, when key K already holds an entry in this phase, compare `(status, sha256(body))`: differ → `key_collisions_divergent++`, else `key_collisions_identical++`; latest-wins unchanged. Manteion computes the same stats at ingest (also catching cross-instance divergence) and reports a per-phase collision rate. **Cost of keeping 1-to-1 latest-wins (asked):** time-varying responses (pagination cursors, timestamps, rotating tokens) and cross-instance divergence are collapsed to the last-observed response, so a workload hitting one key N times gets N identical replays even if the baseline saw N different bodies — a real temporal distortion, now *quantified* by the divergent-collision rate instead of invisible. Divergence ⇒ `VALID_WITH_WARNINGS(collision_rate)`, not `INVALID` — it is a modeling approximation, not a leak. `SEAM(C)`: body normalization (stripping volatile JSON fields before hashing) overlaps data-pool templating; do not build it here — the per-rule strategy downgrade to `exact` (drop body from key, accept collision warnings) is the operator's interim knob.

**Rejected:** hashing all headers (cardinality explosion on Date/trace/auth headers → guaranteed 100% miss); a denylist instead of an allowlist (unknown headers leak in by default — wrong failure direction); keeping FNV-64 for bodies (research instrument; SHA-256's cost is irrelevant at these rates); making `exact` (no body) the default (silent POST-body collisions — silent-wrong loses to loud-wrong, and fail-closed + INVALID makes body-in-key mismatches loud).

### Q4 — Preload integrity

**Decision:** four mechanisms, minimal set that yields "exactly the baseline set, complete, non-leaking":
1. **Replace via staged commit, never merge.** New SDK preload protocol: `begin → chunk* → commit` (wire spec §W). Chunks stage into a buffer keyed `(experiment_id, phase_id)`; `commit` verifies count and checksum, then atomically swaps the staged set in as *the* replay set, dropping any previous set. A half-delivered preload is never visible to replay.
2. **Pinning by construction.** Split the single shared LRU into a `ReplaySet` (immutable map behind an atomic pointer; no eviction, no cap — bounded instead by a `max_bytes` guard at `begin`/`chunk`, default 256 MiB, rejected with 413) and a `RecordBuffer` (export queue feeding the pusher). Eviction of preloaded entries becomes structurally impossible, and recording pressure can no longer evict replay data.
3. **Per-instance completeness gate.** Manteion computes `expected_count` and an order-independent checksum from its NDJSON store (`entry_digest = SHA-256(key || 0x00 || uint16_be(status) || 0x00 || sha256(body))`; `set_checksum = SHA-256(concat(sorted(entry_digests)))` — both sides implement this exact spec). Every live instance of every frozen service must return a matching `commit`. Any mismatch, timeout, zero-entry frozen service, or missing baseline phase → the phase is failed *before* `freezeServices` runs and before load starts. This replaces today's warn-and-continue in `preloadCacheEntries` (`runner.go:469-499`) and the silent "no baseline → skip preload" at `runner.go:474-478`, which currently produces an all-miss (i.e., before INV-1, all-leaking) run at INFO level.
4. **Right-sized transport.** Preload stops riding the 2s command-fanout timeout: a dedicated client path with `MANTEION_PRELOAD_TIMEOUT` (default 60s) per call, chunks capped at ≤ 500 entries or ≤ 4 MiB serialized (whichever first). Chunking subsumes the single-shot case (small sets = 1 chunk) and the commit step is needed for the checksum gate regardless, so this is not extra protocol for its own sake. Do NOT raise the global fanout timeout — 2s is right for tiny freeze/rule commands and raising it would mask hung SDKs.

Ordering stays `preload → freeze → rules → load` (as `enterPhase` already does) but each arrow becomes a verified gate instead of best-effort. Freeze-command fanout failures on frozen services also become phase-fatal (today `freezeServices` warns at `runner.go:447-450` — an un-asserted freeze is the same severity as a failed preload).

**Rejected:** merge-with-TTL (stale entries from prior phases are exactly the bleed we're killing); pinning bits inside a shared LRU (more states to get wrong; the split store deletes the problem); single-shot preload with a big timeout (all-or-nothing retries of tens of MiB, memory spikes, body-size limits — chunk+commit is barely more code and strictly more robust).

### Q5 — Isolation keying: `(experiment_id, phase_id)`

**Decision:** yes — composite `(experiment_id, phase_id)` everywhere: push envelope, drain report, preload begin/commit, fidelity snapshots, counters, and the store path (`experiments/{exp}/phases/{phase}/{service}.ndjson`). But the composite key alone doesn't kill cross-experiment bleed; the ambient lookup does. So: **delete the global "most recently started recording phase" query** — the recording context rides on the compiled rule itself (`CacheBoxContext` on rules whose owning phase is active), the SDK stamps entries from the matched rule, and the push endpoint validates the pair is in `recording|draining` state with no inference fallback. While touching the store schema, fix the `runID`-naming landmine (rename to `phaseID`, add `experimentID`) and route NDJSON appends through a single-writer goroutine — correct under the single-replica assumption, which is hereby flagged as load-bearing (also load-bearing: the in-memory batch-seq dedupe map, drain expected-set, and intent tracker; each gets a `// SINGLE-REPLICA:` comment).

**Downside and its containment:** two concurrent experiments sharing a service are *rule-conflict* irreconcilable (A freezes S, B wants S live) no matter how keys are scoped. Full multi-tenancy is out of proportion for a research instrument, so: admission control — refuse to start an experiment whose service set (frozen services ∪ rule targets across all phases) intersects any running experiment's set, overridable via `MANTEION_ALLOW_CONCURRENT_OVERLAP=true`. Conservative, simple, correct; relax later if needed. Other downsides are trivial: slightly larger envelopes, a storage-layout migration (acceptable — recorded data is per-experiment ephemeral research data).

### Q6 — Fidelity observability

**Decision:** a per-`(experiment_id, phase_id)` counter registry in the SDK — scoping by composite key IS the per-phase reset (a new phase is a new key; no reset races). Minimal set: `replay_hits`, `replay_misses{reason: key_absent | not_committed | body_buffer_failed}`, `record_enqueued`, `record_pushed`, `record_dropped`, `push_rejected_terminal`, `key_collisions_divergent`, `key_collisions_identical`, `replay_age_ms{max,mean}` (served-at minus entry `recorded_at` — this becomes the real staleness number replacing manteion's hardcoded 0), and preload state `{committed, entries, checksum, committed_at}`. Exposure is **pull-based**: `GET /cachebox/fidelity?experiment_id&phase_id` on the SDK; manteion fans out this pull in `finishPhase` for isolation phases (before thaw, so counters are intact) and as the drain-timeout fallback for recording phases. Pull is synchronous and authoritative at exactly the moment the verdict is computed — no last-5-seconds push race, no new periodic traffic. The drain report (Q2) additionally pushes the record-side counters at recording end. Verdict computation (manteion): `INVALID` iff any instance has `replay_misses > 0`, preload uncommitted/mismatched, source recording degraded, or fidelity pull failed (`telemetry_missing`); else `VALID_WITH_WARNINGS` iff phase collision rate > 1%; else `VALID`. Stored on the phase, returned in phase results. `SEAM(D)`: the delta engine reads the verdict; one comment at the harvest/results boundary, no math changes.

**Rejected:** periodic counter push piggybacked on the poll (adds traffic and still races the phase boundary; live dashboards can come later); Prometheus-only exposure (scrape timing is not synchronized to phase boundaries; the control plane, not a scraper, owns the verdict).

## W. Wire contract (shared spec — both sessions implement to THIS, enabling parallel work)

All types live in the **atropos-go root package** (`atroposdk`), which manteion already imports for `CompiledRule`/`RuleSync` (per manteion CLAUDE.md). JSON field names below are normative. All additions are additive/optional for backward compatibility; behavior flips are gated by their presence.

**W1. `CacheBoxContext`** — attached to (a) the cache-box portion of compiled rules, (b) the freeze command body (alongside the existing `DelayRequest`), (c) preload `begin`:
```json
{"experiment_id":"exp-…","phase_id":"phase-…","key_strategy":"canonical_v2","strategy_version":2,"key_headers":["x-tenant-id"],"miss_status":503}
```
`key_headers` are *additions* to the default allowlist, lowercase. `miss_status` optional, default 503.

**W2. Push envelope additions:** `experiment_id` (string), `batch_seq` (int, 1-based, monotonic per (exp, phase, instance)). Per-entry additions: `key_strategy`, `strategy_version`, `recorded_at` (RFC3339Nano), `response_body_sha256` (hex), `request_meta {"method","host","path"}` (debug provenance; not used for matching). Push response: `200 {"accepted":N,"duplicate":false}`; duplicate batch (same seq) → `200 {"accepted":0,"duplicate":true}`; phase not `recording|draining` → `409 {"error":"phase_not_recording"}`.

**W3. Drain report:** `POST {manteion}/api/v1/sdk/cachebox/drain`
```json
{"experiment_id":"…","phase_id":"…","service":"…","instance_id":"…","entries_recorded":12345,"entries_pushed":12345,"entries_dropped":0,"batches_sent":25,"last_batch_seq":25,"key_collisions_divergent":7,"key_collisions_identical":92}
```
Idempotent on (exp, phase, instance); response `200 {"accepted":true}`.

**W4. Preload protocol (manteion → SDK):**
- `POST /cachebox/preload/begin` `{"experiment_id","phase_id","source_phase_id","total_entries":N,"total_chunks":K,"key_strategy":"canonical_v2","strategy_version":2,"key_headers":[…],"max_bytes":268435456}` → `200 {"ok":true}` | `413 {"error":"too_large"}` | `409` (strategy unsupported). `begin` clears any staging for the pair.
- `POST /cachebox/preload/chunk` `{"experiment_id","phase_id","chunk_seq":i,"entries":[…]}` → `200 {"staged_total":n}`; idempotent by `chunk_seq`.
- `POST /cachebox/preload/commit` `{"experiment_id","phase_id","total_entries":N,"checksum":"hex"}` → `200 {"ok":true,"loaded":N,"checksum":"hex"}` on match (atomic swap happens here) | `409 {"ok":false,"loaded":n,"checksum":"hex"}` (staging dropped, no swap).
- `POST /cachebox/preload/abort` `{"experiment_id","phase_id"}` → `200`.

**W5. Checksum (both sides, exact):** `entry_digest = SHA-256(key_bytes || 0x00 || uint16_be(status) || 0x00 || SHA-256(response_body))`; `set_checksum = hex(SHA-256(concat(entry_digests sorted lexicographically as byte strings)))`.

**W6. Fidelity snapshot:** `GET {sdk}/cachebox/fidelity?experiment_id=…&phase_id=…` →
```json
{"instance_id":"…","service":"…","experiment_id":"…","phase_id":"…","replay_hits":10000,"replay_misses":0,"miss_reasons":{"key_absent":0,"not_committed":0,"body_buffer_failed":0},"record_enqueued":0,"record_pushed":0,"record_dropped":0,"push_rejected_terminal":0,"key_collisions_divergent":0,"key_collisions_identical":0,"replay_age_ms":{"max":61234,"mean":30500},"preload":{"committed":true,"entries":12345,"checksum":"…","committed_at":"…"}}
```

**W7. `canonical_v2` key framing (exact):** `key = "v2:" + hex(SHA-256(frame))`; `frame = Σ uvarint(len(c))||c` over components in order: `"v2"`, `strings.ToUpper(method)`, `strings.ToLower(url.Host)`, `url.Path` (raw), canonical query (split `RawQuery` on `&`, byte-sort segments, join `&`; empty string if none), header fingerprint (§Q3), `SHA-256(body)` raw bytes (empty component if no body).

## 4. Sequencing

The three CRITICALs are the spine; everything else hangs off them.

1. **M0 — Stop the leak (ATRO-1).** One file, no dependencies, deployable alone. From this commit forward no frozen service can silently call a live downstream — the single worst failure mode is dead. Its tests also become the ratchet protecting the later refactors.
2. **M1 — Unblock parallelism (ATRO-2).** Push the wire types; both sessions now proceed independently against §W. Manteion session starts with MANT-3 (internal storage/ingest refactor) in the meantime.
3. **M2 — Trust the recording (ATRO-4, ATRO-5 ∥ MANT-3, MANT-2).** Drain barrier live: recorded coverage becomes verified-complete instead of a floor; the 409 loss window is gone by construction.
4. **M3 — Trust the preload (ATRO-3, ATRO-6 ∥ MANT-1, MANT-4).** Correct keys (POST-body collision fixed, operator strategy authoritative), and load can only start against verified byte-exact frozen sets.
5. **M4 — Kill the bleed (MANT-5).** Strategy preflight + admission control; ambient recording lookup already deleted in MANT-4.
6. **M5 — Prove it (ATRO-7 ∥ MANT-6).** Every run ends with a stored VALID/INVALID verdict; fidelity is measured, not assumed. This is the milestone that turns the platform into an instrument.

Full-loop e2e after M5: record → drain(clean) → preload(verified) → freeze → load → verdict VALID on a healthy run; then each induced fault (killed instance pre-phase, deleted entry mid-phase, silenced pusher) produces the specific named failure/INVALID it should.

## 5. Critique

- **The root defect is architectural, and the plan keeps its cure explicit:** the cache-box was built as a *cache* (miss → fetch and warm, `cachebox.go:77` says so) and then reused as a *measurement instrument*. Every CRITICAL traces to that dual identity. The split store + fail-closed dispatch removes the shared path; keep them separated forever, even when tempted to "reuse the replay set for warm passthrough."
- **The hidden fourth critical:** `runner.go:474-478` — no completed baseline → INFO log → preload silently skipped → the isolation load runs all-miss. Before ATRO-1 that is an *all-leak* run that looks superficially plausible in the results. It is fixed by MANT-1, but it deserved CRITICAL billing in the audit.
- **Three state-distribution paths is one too many.** Rules poll (B), command fanout push (A), and register-time intent piggyback all carry overlapping truth; the dead key strategy died precisely in the gap between them. This plan threads context through all three consistently but does not consolidate them — flagging: medium-term, collapse to a single versioned desired-state document per service that SDKs poll, with fanout reserved for time-critical nudges. Not now; it would blow the minimal-change constraint.
- **Zero-tolerance INVALID will bite nondeterministic workloads, and that is correct.** Request bodies containing timestamps/UUIDs will produce novel keys under freeze → fail-closed misses → INVALID. That is the instrument telling the truth: the workload is not the fixed workload the causal design assumes. The escape hatches are per-service strategy `exact` (accept collision warnings instead) or `SEAM(C)` body normalization. Resist adding a miss-tolerance threshold until real runs prove a specific noise floor.
- **Risks in this task list:** (1) `draining` enum migration — append-only epoch-2 migration is fine, but `TransitionPhase` source-set changes touch the orchestrator's race discipline; the CAS winner-only pattern must be preserved exactly (MANT-2's tests assert it). (2) Preload memory double-residency during swap (staging + live) — bounded by `max_bytes` accounting both; do not skip that accounting. (3) Drain timeout vs SDK poll interval coupling is a config foot-gun — the ≥ 3× constraint must be documented at the config definition. (4) The expected-instance set depends on registry freshness; a crashed-but-registered pod costs a full drain timeout per phase — acceptable, but worth a log line naming the laggard early. (5) Single-replica assumptions (batch-seq dedupe, drain state, NDJSON writer, intent tracker) are now load-bearing in four places — each carries a `// SINGLE-REPLICA:` marker so a future HA effort can grep its blast radius.
- **Deliberately not built:** per-entry TTLs, replay-set persistence across SDK restarts (a restart mid-phase should fail the phase via preload/commit absence and telemetry-missing verdict — restarting and resuming would hide a discontinuity), periodic counter push, multi-response-per-key replay, and any body normalization. Each is either out of scope, hides a failure, or belongs to C/D.
